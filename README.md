# Adaptive AI Widget

Адаптивный ИИ-виджет для сайтов с локальным ИИ на Ollama: один `<script>` — виджет автоматически подстраивает стиль и отвечает на основе данных страницы.

## Что нужно запустить для работы агента

| Режим | Что запускается | Когда хватает |
|---|---|---|
| **Виджет (обязательно)** | Просто встроить `<script>` в страницу | Всегда — без этого агента нет |
| **AI-модель (опционально)** | Ollama (`ollama serve`) или облако по API-ключу | Если нужны именно ИИ-ответы, а не только поиск по сайту |
| **Сервер поддержки (опционально)** | `node server/server.js` | Email-уведомления, операторы, статистика, настройки агента в админке |

Минимальная работающая конфигурация — один `<script>`: виджет сам собирает данные сайта и отвечает поиском (без AI-модели). Ollama нужна только для ответов от LLM, а сервер — только для функций поддержки.

## Быстрый старт

### 1. Виджет

Встроить в страницу `widget/adaptive-widget.js` (см. «Подключение на свой сайт»). Готовое демо — `demo/index.html`.

### 2. (опционально) Локальный ИИ — Ollama

```bash
# Windows: скачайте с https://ollama.com/download/windows, затем:
ollama-start.bat      # установка модели + запуск Ollama (CPU-режим) -> демо
```

- Демо: откройте `demo/index.html` (виджет ходит напрямую в `http://localhost:11434`).
- `ollama-start.bat` делает всё сам: при необходимости качает модель `qwen2.5:3b`, запускает сервер в **CPU-режиме** (`CUDA_VISIBLE_DEVICES=-1`) и с `OLLAMA_ORIGINS=*` — так демо открывается даже из `file://`, а на старых GPU (GTX 10xx и т.п.) нет падения llama-server из-за несовместимого PTX.
- Перед запуском закройте трей Ollama (`ollama app`), иначе порт `11434` будет занят её сервером.

### 3. (опционально) Сервер поддержки

```bash
copy server\config.example.json server\config.json   # впишите свой adminToken
node server\server.js                                 # по умолчанию порт 3000
```

- Демо-страница виджета: `http://localhost:3000/demo`
- Админ-панель агентов: `http://localhost:3000/admin` — чаты, статистика, настройки агента
- AI-конфиг живёт в `server/config.json` (не коммитится в git) и редактируется из админки
- Если в конфиге задан `adminToken`, админка при первом обращении спросит пароль и запомнит его в браузере (только для этого хоста)

## Как это работает

1. **Экстракция стиля** — читает CSS-переменные (`--brand`, `--accent`), цвета кнопок, шрифт, тему (dark/light)
2. **Экстракция знаний** — парсит JSON-LD, заголовки, FAQ, товары, контакты из DOM
3. **Поиск** — взвешенный поиск по извлечённым токенам (заголовок весит x3)
4. **ИИ** — RAG: контекст из знаний сайта + вопрос → Ollama (локально) или облачный API (OpenAI/OpenRouter/Groq/Mistral), вывод через OpenAI-совместимый формат
5. **Backend-режим** — при подключённом сервере (`backend`): запрос email до первого вопроса (ответ оператора придёт на почту, если вкладку закроют), ИИ отвечает на сервере, диалог можно передать живому оператору, все чаты и письма логируются

## Режимы работы

**Локальный (один файл, без сервера):** всё как в MVP — RAG-поиск и ИИ прямо в браузере. Виджет подхватывает `provider/model/instructions` из `window.ADAPTIVE_WIDGET` на странице.

**Backend-режим (с сервером поддержки):** конфигурация ИИ, инструкции, логи чатов, email-уведомления и переключение на операторов живут на сервере. Агенты настраивают и обслуживают всё через админ-панель `/admin`, клиент видит ответы и события в реальном времени по SSE.

У ИИ-агента на сервере **два режима работы** (переключаются в админке или `agentMode` в конфиге):

- `agentMode: "rag"` — ответы ищет сервер и отдаёт весь контекст модели одним запросом. Проще и быстрее.
- `agentMode: "tools"` — модель ходит в данные сайта через инструменты (tool-calling) и сама решает, когда и что искать.

Подробности, плюсы и минусы — в [Приложении: режимы ИИ-агента](docs/MODES_COMPARISON.md).

```html
<script>
window.ADAPTIVE_WIDGET = {
  backend: 'https://chat.yoursite.ru',  // URL сервера
  supportEmail: 'support@deworld.su',   // почта, на которую пишут операторы
  askEmail: true                        // спросить email перед чатом
};
</script>
```

Без email-шага просто пропустите `askEmail` или выставьте `false`. Виджет полностью работоспособен и без сервера.

## Архитектура

**Локальный режим (MVP):**

```
Пользователь → Вопрос
        ↓
┌───────────────────────────────────┐
│       Адаптивный ИИ-Агент        │
├───────────────────────────────────┤
│  1. Экстракция стиля сайта       │  ← getComputedStyle(), CSS variables
│  2. Экстракция знаний            │  ← JSON-LD, headings, FAQ, products
│  3. Построение индекса            │  ← tokenization, scoring
│  4. Поиск ответа                 │  ← weighted TF matching
│  5. ИИ-ответ (RAG)               │  ← Ollama или облако, контекст + вопрос
└───────────────────────────────────┘
        ↓
  Ответ с источником
```

**Backend-режим (сервер поддержки):**

```
Клиент (виджет)                Сервер                         Агент поддержки
┌─────────────────┐           ┌───────────────────────────┐    ┌──────────────┐
│ email → /api/init│	→	│  логи чатов (NDJSON)       │    │  /admin      │
│ знания+промпт    │	→	│  ответ: кэш → Q&A → LLM/поиск│←→	│  ответы,      │
│ вопрос → message │	→	│  handoff → оператор          │    │  инструкции  │
│ событие с SSE    │	←	│  reply via SSE / email      │    │  Q&A, порог  │
│ чипы: /api/faq   │	←	│  популярные + Q&A вопросы  │    │  ИИ↔оператор │
└─────────────────┘           └───────────────────────────┘    └──────────────┘
```

Порядок ответа агента на сервере: **кэш** (повторный вопрос — мгновенно, `answers-cache.json`) → **база Q&A** из конфига (работает даже без ИИ-модели, распознаёт перефразировки по порогу `qaThreshold`) → **LLM** → **поиск по данным сайта** → честное «не знаю» + контакт поддержки.

## Подключение на свой сайт

```html
<script>
window.ADAPTIVE_WIDGET = {
  siteName: 'Мой магазин',
  aiEnabled: true,
  model: 'qwen2.5:3b'
};
</script>
<script src="widget/adaptive-widget.js" defer></script>
```

### Альтернативные LLM

Виджет умеет работать с любым OpenAI-совместимым API — локальным (Ollama) или облачным (OpenAI, OpenRouter, Groq, Mistral, свой сервер):

```html
<script>
window.ADAPTIVE_WIDGET = {
  aiEnabled: true,
  provider: 'openai',         // openai | openrouter | groq | mistral | ollama | custom
  apiKey: 'sk-...',           // ключ облачного API
  model: 'gpt-4o-mini'        // если не указан — берётся модель по умолчанию провайдера
};
</script>
```

Если `provider` не задан, виджет выбирает его автоматически: есть `apiKey` → `openai` (+ `gpt-4o-mini`), нет → локальная `ollama`.

Свой OpenAI-совместимый сервер (или прокси):

```html
<script>
window.ADAPTIVE_WIDGET = {
  aiEnabled: true,
  provider: 'custom',
  endpoint: 'https://my-ai.example.com/v1/chat/completions',
  apiKey: 'secret',
  model: 'my-model'
};
</script>
```

## Конфигурация

| Параметр | По умолчанию | Описание |
|---|---|---|
| `siteName` | заголовок страницы | Имя, показываемое в шапке виджета |
| `position` | `'right'` | Позиция: `'right'` или `'left'` |
| `aiEnabled` | `true` | Включить LLM-режим |
| `provider` | `'auto'` | `'ollama'`, `'openai'`, `'openrouter'`, `'groq'`, `'mistral'`, `'custom'` или `'auto'` |
| `model` | из провайдера | Модель (`qwen2.5:3b`, `gpt-4o-mini`, `openrouter/auto` и т.д.) |
| `apiKey` | `''` | API-ключ (не нужен для Ollama) |
| `endpoint` | Ollama localhost | URL OpenAI-совместимого API (для `custom`) |
| `backend` | `''` | URL сервера поддержки (включает email/операторов/логи) |
| `supportEmail` | `'support@deworld.su'` | Адрес поддержки (отправка ответов/задач) |
| `askEmail` | `true` при `backend` | Спросить email перед первым вопросом |
| `instructions` | `''` | Пользовательские инструкции для ИИ (в backend-режиме настраиваются в админке) |
| `autoOpen` | `true` | Автопоявление подсказки через 1.5с |
| `teaser` | *(текст из языка)* | Текст всплывающей подсказки |
| `lang` | определение из `<html lang>` | Язык интерфейса (`'ru'` / `'en'`) |

### Настройки агента — в админке

Настройки ИИ убраны из виджета (здесь больше нет шестерёнки и панели настроек). В backend-режиме их ведёт оператор в админ-панели — вкладка **«Настройки агента»**: провайдер (`ollama`/`openai`/`openrouter`/`groq`/`mistral`/`custom`), endpoint, модель, API-ключ, адрес отправителя `from`, флаг «спрашивать email» и глобальные инструкции. Сохранение пишет их в `server/config.json` (PUT `/api/config`).

Вкладка **«Статистика»** показывает: количество сайтов с агентом, пользователей онлайн, ответов агента, нерешённых запросов, среднюю оценку (виджет предлагает её при закрытии диалога) — плюс таблицы популярных и нерешённых запросов (GET `/api/stats`). Оценка из виджета приходит на сервер как POST `/api/chat/:id/rating`.

### Статус подключения ИИ

В шапке виджета отображается состояние: `AI: qwen2.5:3b · Ollama` (зелёный), `AI: gpt-4o-mini · OpenAI` (зелёный), или нейтральное `ИИ отключён · отвечаю по данным сайта` (жёлтое). Последнее — **не** ошибка: без рабочей LLM виджет честно отвечает поиском по данным страницы.

## Backend и файлы данных

| Файл / маршрут | Назначение |
|---|---|
| `server/config.json` | AI-конфиг сервера: `provider`, `endpoint`, `model`, `from`, `instructions`, `adminToken`, `smtp` (не в git); редактируется из админки |
| `config.example.json` | Шаблон конфига |
| `server/data/chats.json` | Вся история чатов (JSON) |
| `server/data/chatlog.ndjson` | Аппенд-лог каждого события чата |
| `server/data/email.log.ndjson` | Исходящие письма (outbox) |
| `/api/health` | Проверка сервера |
| `/api/init` | Первичная регистрация чата (знания + промпт + email клиента) |
| `/api/chat/:id/message` | Сообщение (AI-ответ на сервере / пересылка оператору) |
| `/api/chat/:id/rating` | Оценка диалога клиентом (звёзды 1–5) |
| `/api/chat/:id/{handoff,mode,reply,instructions,events,full,close}` | Перевод оператору, возврат ИИ, ответ оператора, инструкции, SSE-канал, снимок, закрытие |
| `/api/stats` | Статистика: сайты, онлайн, ответы, оценки, популярные/нерешённые запросы, размер/попадания кэша ответов |
| `/api/config` | GET/PUT — настройки агента: провайдер, модель, инструкции, база Q&A, порог схожести (админка, требуют `adminToken`) |
| `/api/faq` | Частые вопросы для чипов виджета: популярные запросы + Q&A из конфига (публичный) |
| `/admin` | Админ-панель агентов: вкладки «Чаты», «Статистика», «Настройки агента» |
| `/demo` | Демо-страница виджета (GadgetHub), виджет подтягивается с этого же сервера |
| `server/data/answers-cache.json` | Кэш ответов агента (вопрос → ответ), повторные вопросы не тратят токены |

## Демо-сценарии

**Интернет-магазин (GadgetHub):**
- «Сколько стоят наушники Aurora X?» → цена из JSON-LD
- «Как вернуть товар?» → ответ из FAQ
- «Куда позвонить?» → контакты из данных сайта

**Игровая платформа (Nebula Commerce):**
- «Как быстро приходит ключ?» → ответ из FAQ  
- «Можно ли оплатить картами РФ?» → ответ из контента
- «Как связаться с поддержкой?» → контакты
