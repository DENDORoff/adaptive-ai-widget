# Adaptive AI Widget

Адаптивный ИИ-виджет для сайтов с локальным ИИ на Ollama: один `<script>` — виджет автоматически подстраивает стиль и отвечает на основе данных страницы.

## Быстрый старт

### 1. Установить Ollama

```bash
# Windows
# Скачайте с https://ollama.com/download/windows
# Или запустите:
setup-ollama.bat
```

### 2. Скачать модель

```bash
ollama pull qwen2.5:3b
```

### 3. Запустить Ollama

```bash
ollama serve
```

### 4. Открыть демо

```bash
# Светлая тема (GadgetHub)
start demo\index.html

# Тёмная тема (Nebula Commerce)  
start demo\dark-store.html
```

### 5. Сервер поддержки (email-уведомления, операторы, логи чатов)

```bash
copy server\config.example.json server\config.json   # впишите свой adminToken
node server\server.js                                 # по умолчанию порт 3000
npm run dev                                           # (опционально) всё из одного файла
```

- Виджет: `http://localhost:3000/`
- Админ-панель агентов поддержки: `http://localhost:3000/admin`
- AI-конфиг смотрится в `server/config.json` (не коммитится в git)

## Как это работает

1. **Экстракция стиля** — читает CSS-переменные (`--brand`, `--accent`), цвета кнопок, шрифт, тему (dark/light)
2. **Экстракция знаний** — парсит JSON-LD, заголовки, FAQ, товары, контакты из DOM
3. **Поиск** — взвешенный поиск по извлечённым токенам (заголовок весит x3)
4. **ИИ** — RAG: контекст из знаний сайта + вопрос → Ollama (локально) или облачный API (OpenAI/OpenRouter/Groq/Mistral), вывод через OpenAI-совместимый формат
5. **Backend-режим** — при подключённом сервере (`backend`): запрос email до первого вопроса (ответ оператора придёт на почту, если вкладку закроют), ИИ отвечает на сервере, диалог можно передать живому оператору, все чаты и письма логируются

## Режимы работы

**Локальный (один файл, без сервера):** всё как в MVP — RAG-поиск и ИИ прямо в браузере, настройки ИИ (инструкции/промпт/знания) редактируются в самом виджете (кнопка шестерёнки) и хранятся в `localStorage`.

**Backend-режим (с сервером поддержки):** конфигурация ИИ, логи чатов, email-уведомления и переключение на операторов живут на сервере, агенты работают через админ-панель, клиент видит всё в реальном времени по SSE.

```html
<script>
window.ADAPTIVE_WIDGET = {
  backend: 'https://chat.yoursite.ru',  // URL сервера
  supportEmail: 'support@deworld.su',   // почта, на которую пишут операторы
  askEmail: true                        // спросить email перед чатом
};
</script>
```

Без email-шага просто пропустите `askEmail` или выставьте `false`. Виджет полностью работоспособен и без сервера.

## Архитектура

**Локальный режим (MVP):**

```
Пользователь → Вопрос
        ↓
┌───────────────────────────────────┐
│       Адаптивный ИИ-Агент        │
├───────────────────────────────────┤
│  1. Экстракция стиля сайта       │  ← getComputedStyle(), CSS variables
│  2. Экстракция знаний            │  ← JSON-LD, headings, FAQ, products
│  3. Построение индекса            │  ← tokenization, scoring
│  4. Поиск ответа                 │  ← weighted TF matching
│  5. ИИ-ответ (RAG)               │  ← Ollama или облако, контекст + вопрос
└───────────────────────────────────┘
        ↓
  Ответ с источником
```

**Backend-режим (сервер поддержки):**

```
Клиент (виджет)                Сервер                         Агент поддержки
┌─────────────────┐           ┌───────────────────────────┐    ┌──────────────┐
│ email → /api/init│	→	│  логи чатов (NDJSON)       │    │  /admin      │
│ знания+промпт    │	→	│  ИИ-ответ (LLM/поиск)       │←→	│  ответы,     │
│ вопрос → message │	→	│  handoff → оператор          │    │  инструкции  │
│ событие с SSE    │	←	│  reply via SSE / email      │    │  ИИ↔оператор │
└─────────────────┘           └───────────────────────────┘    └──────────────┘
```

## Подключение на свой сайт

```html
<script>
window.ADAPTIVE_WIDGET = {
  siteName: 'Мой магазин',
  aiEnabled: true,
  model: 'qwen2.5:3b'
};
</script>
<script src="widget/adaptive-widget.js" defer></script>
```

### Альтернативные LLM

Виджет умеет работать с любым OpenAI-совместимым API — локальным (Ollama) или облачным (OpenAI, OpenRouter, Groq, Mistral, свой сервер):

```html
<script>
window.ADAPTIVE_WIDGET = {
  aiEnabled: true,
  provider: 'openai',         // openai | openrouter | groq | mistral | ollama | custom
  apiKey: 'sk-...',           // ключ облачного API
  model: 'gpt-4o-mini'        // если не указан — берётся модель по умолчанию провайдера
};
</script>
```

Если `provider` не задан, виджет выбирает его автоматически: есть `apiKey` → `openai` (+ `gpt-4o-mini`), нет → локальная `ollama`.

Свой OpenAI-совместимый сервер (или прокси):

```html
<script>
window.ADAPTIVE_WIDGET = {
  aiEnabled: true,
  provider: 'custom',
  endpoint: 'https://my-ai.example.com/v1/chat/completions',
  apiKey: 'secret',
  model: 'my-model'
};
</script>
```

## Конфигурация

| Параметр | По умолчанию | Описание |
|---|---|---|
| `siteName` | заголовок страницы | Имя, показываемое в шапке виджета |
| `position` | `'right'` | Позиция: `'right'` или `'left'` |
| `aiEnabled` | `true` | Включить LLM-режим |
| `provider` | `'auto'` | `'ollama'`, `'openai'`, `'openrouter'`, `'groq'`, `'mistral'`, `'custom'` или `'auto'` |
| `model` | из провайдера | Модель (`qwen2.5:3b`, `gpt-4o-mini`, `openrouter/auto` и т.д.) |
| `apiKey` | `''` | API-ключ (не нужен для Ollama) |
| `endpoint` | Ollama localhost | URL OpenAI-совместимого API (для `custom`) |
| `backend` | `''` | URL сервера поддержки (включает email/операторов/логи) |
| `supportEmail` | `'support@deworld.su'` | Адрес поддержки (отправка ответов/задач) |
| `askEmail` | `true` при `backend` | Спросить email перед первым вопросом |
| `showConfig` | `true` | Показывать кнопку настроек ИИ (шестерёнку) |
| `adminPass` | `''` | Пароль администратора настроек: если задан, обычные посетители видят шестерёнку, но открыть настройки может только тот, кто введёт пароль |
| `instructions` | `''` | Пользовательские инструкции для ИИ (редактируются в виджете) |
| `autoOpen` | `true` | Автопоявление подсказки через 1.5с |
| `teaser` | *(текст из языка)* | Текст всплывающей подсказки |
| `lang` | определение из `<html lang>` | Язык интерфейса (`'ru'` / `'en'`) |

### Настройки ИИ в виджете (шестерёнка)

Кнопка шестерёнки в шапке открывает панель настроек: инструкции для ИИ (сохраняются в `localStorage` и, при `backend`, синхронизируются на сервер), собранный промпт, список извлечённых знаний и кнопку повторного сбора данных сайта. Панель закрывается кнопкой ✕ (или повторным кликом по шестерёнке).

По умолчанию настройки открыты всем — так удобно на этапе разработки. **В проде задайте `adminPass`**: тогда при клике на шестерёнку будет запрошен пароль, и только после его ввода откроется панель (права админа запоминаются в `localStorage` браузера). А если гейт не нужен вовсе — скройте шестерёнку: `showConfig: false`.

### Статус подключения ИИ

В шапке виджета отображается состояние: `AI: qwen2.5:3b · Ollama` (зелёный), `AI: gpt-4o-mini · OpenAI` (зелёный), или нейтральное `ИИ отключён · отвечаю по данным сайта` (жёлтое). Последнее — **не** ошибка: без рабочей LLM виджет честно отвечает поиском по данным страницы.

## Backend и файлы данных

| Файл / маршрут | Назначение |
|---|---|
| `server/config.json` | AI-конфиг сервера: `provider`, `endpoint`, `model`, `from`, `adminToken`, `smtp` (не в git) |
| `config.example.json` | Шаблон конфига |
| `server/data/chats.json` | Вся история чатов (JSON) |
| `server/data/chatlog.ndjson` | Аппенд-лог каждого события чата |
| `server/data/email.log.ndjson` | Исходящие письма (outbox) |
| `/api/health` | Проверка сервера |
| `/api/init` | Первичная регистрация чата (знания + промпт + email клиента) |
| `/api/chat/:id/message` | Сообщение (AI-ответ на сервере / пересылка оператору) |
| `/api/chat/:id/{handoff,mode,reply,instructions,events,full,close}` | Перевод оператору, возврат ИИ, ответ оператора, инструкции, SSE-канал, снимок, закрытие |
| `/admin` | Админ-панель агентов: список чатов, ответы, перевод «ИИ → оператор», редактор инструкций |

## Демо-сценарии
