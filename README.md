# Adaptive AI Widget

Адаптивный ИИ-виджет для сайтов с локальным ИИ на Ollama: один `<script>` — виджет автоматически подстраивает стиль и отвечает на основе данных страницы.

## Что нужно запустить для работы агента

| Режим | Что запускается | Когда хватает |
|---|---|---|
| **Виджет (обязательно)** | Просто встроить `<script>` в страницу | Всегда — без этого агента нет |
| **AI-модель (опционально)** | Ollama (`ollama serve`) или облако по API-ключу | Если нужны именно ИИ-ответы, а не только поиск по сайту |
| **Сервер поддержки (опционально)** | `node server/server.js` | Email-уведомления, операторы, статистика, настройки агента в админке |

Минимальная работающая конфигурация — один `<script>`: виджет сам собирает данные сайта и отвечает поиском (без AI-модели). Ollama нужна только для ответов от LLM, а сервер — только для функций поддержки.

## Быстрый старт

### 1. Виджет

Встроить в страницу `widget/adaptive-widget.js` (см. «Подключение на свой сайт»). Демо:
- `demo/index.html`, `demo/dark-store.html` — виджет напрямую ходит в Ollama (локальный режим, без сервера).
- `demo/backend.html` — виджет подключён к серверу поддержки: каждый диалог и статистика появляются в админке `/admin`. Открывайте его как файл (`file://`) или через `http://localhost:3000/demo/backend.html`.

### 2. (опционально) Локальный ИИ — Ollama

```bash
# Windows: скачайте с https://ollama.com/download/windows, затем:
ollama-start.bat      # установка модели + запуск Ollama (CPU-режим) -> демо
```

- Демо: откройте `demo/index.html` (виджет ходит напрямую в `http://localhost:11434`).
- `ollama-start.bat` делает всё сам: при необходимости качает модель `qwen2.5:3b`, запускает сервер в **CPU-режиме** (`CUDA_VISIBLE_DEVICES=-1`) и с `OLLAMA_ORIGINS=*` — так демо открывается даже из `file://`, а на старых GPU (GTX 10xx и т.п.) нет падения llama-server из-за несовместимого PTX.
- Перед запуском закройте трей Ollama (`ollama app`), иначе порт `11434` будет занят её сервером.

### 3. (опционально) Сервер поддержки

```bash
copy server\config.example.json server\config.json   # впишите свой adminToken
node server\server.js                                 # по умолчанию порт 3000
```

- Демо-страница виджета: `http://localhost:3000/demo`
- Админ-панель агентов: `http://localhost:3000/admin` — чаты, статистика, настройки агента
- AI-конфиг живёт в `server/config.json` (не коммитится в git) и редактируется из админки
- Если в конфиге задан `adminToken`, админка при первом обращении спросит пароль и запомнит его в браузере (только для этого хоста)

## Как это работает

1. **Экстракция стиля** — читает CSS-переменные (`--brand`, `--accent`), цвета кнопок, шрифт, тему (dark/light). Если фирменных цветов нет — может спросить палитру у LLM (`aiStyle`). Виджет можно перекрашивать на лету: `window.AdaptiveWidget.refresh()` перечитывает стиль страницы и плавно меняет палитру без перезагрузки
2. **Экстракция знаний** — парсит JSON-LD, заголовки, FAQ, товары, контакты из DOM, а также изображения (`readImages`; опционально — vision-описание, `vision`)
3. **Поиск** — взвешенный поиск по извлечённым токенам (заголовок весит x3)
4. **ИИ** — RAG: контекст из знаний сайта + вопрос → Ollama (локально) или облачный API (OpenAI/OpenRouter/Groq/Mistral), вывод через OpenAI-совместимый формат
5. **Backend-режим** — при подключённом сервере (`backend`): спросить email до первого вопроса (можно пропустить — `askEmail: 'optional'`), ИИ отвечает на сервере, диалог можно передать живому оператору, новые ответы приходят со звуком и бейджем, все чаты и письма логируются, старые тикеты удаляются по TTL

## Режимы работы

**Локальный (один файл, без сервера):** всё как в MVP — RAG-поиск и ИИ прямо в браузере. Виджет подхватывает `provider/model/instructions` из `window.ADAPTIVE_WIDGET` на странице.

**Backend-режим (с сервером поддержки):** конфигурация ИИ, инструкции, логи чатов, email-уведомления и переключение на операторов живут на сервере. Агенты настраивают и обслуживают всё через админ-панель `/admin`, клиент видит ответы и события в реальном времени по SSE.

У ИИ-агента на сервере **два режима работы** (переключаются в админке или `agentMode` в конфиге):

- `agentMode: "rag"` — ответы ищет сервер и отдаёт весь контекст модели одним запросом. Проще и быстрее.
- `agentMode: "tools"` — модель ходит в данные сайта через инструменты (tool-calling) и сама решает, когда и что искать.

Подробности, плюсы и минусы — в [Приложении: режимы ИИ-агента](docs/MODES_COMPARISON.md).

```html
<script>
window.ADAPTIVE_WIDGET = {
  backend: 'https://chat.yoursite.ru',  // URL сервера
  supportEmail: 'support@deworld.su',   // почта, на которую пишут операторы
  askEmail: 'optional'                  // email рекомендуем, но можно пропустить (Enter без почты)
};
</script>
```

`askEmail: true` — email обязателен, `'optional'` — можно пропустить, `false` — не спрашивать. Виджет полностью работоспособен и без сервера.

## Архитектура

**Локальный режим (MVP):**

```
Пользователь → Вопрос
        ↓
┌───────────────────────────────────┐
│       Адаптивный ИИ-Агент        │
├───────────────────────────────────┤
│  1. Экстракция стиля сайта       │  ← getComputedStyle(), CSS variables
│  2. Экстракция знаний            │  ← JSON-LD, headings, FAQ, products
│  3. Построение индекса            │  ← tokenization, scoring
│  4. Поиск ответа                 │  ← weighted TF matching
│  5. ИИ-ответ (RAG)               │  ← Ollama или облако, контекст + вопрос
└───────────────────────────────────┘
        ↓
  Ответ с источником
```

**Backend-режим (сервер поддержки):**

```
Клиент (виджет)                Сервер                         Агент поддержки
┌─────────────────┐           ┌───────────────────────────┐    ┌──────────────┐
│ email → /api/init│	→	│  логи чатов (NDJSON)       │    │  /admin      │
│ знания+промпт    │	→	│  ответ: кэш → Q&A → LLM/поиск│←→	│  ответы,      │
│ вопрос → message │	→	│  handoff → оператор          │    │  инструкции  │
│ событие с SSE    │	←	│  reply via SSE / email      │    │  Q&A, порог  │
│ чипы: /api/faq   │	←	│  популярные + Q&A вопросы  │    │  ИИ↔оператор │
└─────────────────┘           └───────────────────────────┘    └──────────────┘
```

Порядок ответа агента на сервере: **кэш** (повторный вопрос — мгновенно, `answers-cache.json`) → **база Q&A** из конфига (работает даже без ИИ-модели, распознаёт перефразировки по порогу `qaThreshold`) → **LLM** → **поиск по данным сайта** → честное «не знаю» + контакт поддержки.

## Подключение на свой сайт

```html
<script>
window.ADAPTIVE_WIDGET = {
  siteName: 'Мой магазин',
  aiEnabled: true,
  model: 'qwen2.5:3b'
};
</script>
<script src="widget/adaptive-widget.js" defer></script>
```

### Альтернативные LLM

Виджет умеет работать с любым OpenAI-совместимым API — локальным (Ollama) или облачным (OpenAI, OpenRouter, Groq, Mistral, свой сервер):

```html
<script>
window.ADAPTIVE_WIDGET = {
  aiEnabled: true,
  provider: 'openai',         // openai | openrouter | groq | mistral | ollama | custom
  apiKey: 'sk-...',           // ключ облачного API
  model: 'gpt-4o-mini'        // если не указан — берётся модель по умолчанию провайдера
};
</script>
```

Если `provider` не задан, виджет выбирает его автоматически: есть `apiKey` → `openai` (+ `gpt-4o-mini`), нет → локальная `ollama`.

Свой OpenAI-совместимый сервер (или прокси):

```html
<script>
window.ADAPTIVE_WIDGET = {
  aiEnabled: true,
  provider: 'custom',
  endpoint: 'https://my-ai.example.com/v1/chat/completions',
  apiKey: 'secret',
  model: 'my-model'
};
</script>
```

## Отправка писем (SMTP)

По умолчанию сервер ничего не отправляет по-настоящему: письма видны в `server/data/email.log.ndjson` (outbox) и в админке. Чтобы ответы оператора реально уходили клиенту, укажите SMTP в админке (**Настройки → Почта**) или в `server/config.json`:

```json
"smtp": {
  "host": "smtp.yandex.ru",
  "port": 465,
  "secure": true,
  "user": "support@deworld.su",
  "pass": "app-password",
  "from": "support@deworld.su"
}
```

- Поддерживаются implicit TLS (порт 465) и STARTTLS (587). SMTP-клиент написан на встроенных `net`/`tls` — сторонних пакетов не нужно.
- Для Яндекс.Почты, Gmail и Mail.ru нужен **пароль приложения**, а не обычный пароль. Пресеты провайдеров есть в админке.
- Кнопка **«Отправить тестовое письмо»** вызывает `POST /api/smtp/test` и показывает, ушло ли письмо через SMTP или попало в outbox.
- Пароль SMTP никогда не отдаётся обратно в `GET /api/config`.

## Хранение тикетов (TTL)

`ticketTtlDays` в админке (**Настройки**) задаёт, сколько дней хранить диалоги. `0` — хранить бессрочно. Проверка запускается при старте сервера и раз в час; устаревшие тикеты удаляются из `chats.json`. Значение по умолчанию — `14`.

Подробно — в [docs/FEATURES.md](docs/FEATURES.md): AI-подбор стиля при отсутствии фирменных цветов, чтение изображений в знания (и опциональный vision), необязательный email, звук/бейдж непрочитанного, TTL-очистка тикетов, база инструкций и настоящая SMTP-отправка.

## Конфигурация

| Параметр | По умолчанию | Описание |
|---|---|---|
| `siteName` | заголовок страницы | Имя, показываемое в шапке виджета |
| `position` | `'right'` | Позиция: `'right'` или `'left'` |
| `aiEnabled` | `true` | Включить LLM-режим |
| `provider` | `'auto'` | `'ollama'`, `'openai'`, `'openrouter'`, `'groq'`, `'mistral'`, `'custom'` или `'auto'` |
| `model` | из провайдера | Модель (`qwen2.5:3b`, `gpt-4o-mini`, `openrouter/auto` и т.д.) |
| `apiKey` | `''` | API-ключ (не нужен для Ollama) |
| `endpoint` | Ollama localhost | URL OpenAI-совместимого API (для `custom`) |
| `backend` | `''` | URL сервера поддержки (включает email/операторов/логи) |
| `supportEmail` | `'support@deworld.su'` | Адрес поддержки (отправка ответов/задач) |
| `askEmail` | `'optional'` при `backend` | Спросить email перед первым вопросом: `true` — обязательно, `'optional'` — рекомендуем, но можно пропустить (Enter без почты), `false` — не спрашивать |
| `instructions` | `''` | Пользовательские инструкции для ИИ (в backend-режиме настраиваются в админке) |
| `autoOpen` | `true` | Автопоявление подсказки через 1.5с |
| `teaser` | *(текст из языка)* | Текст всплывающей подсказки |
| `lang` | определение из `<html lang>` | Язык интерфейса (`'ru'` / `'en'`) |
| `aiStyle` | `true` | Если на странице нет фирменных цветов — спросить палитру у LLM (иначе остаются цвета по умолчанию) |
| `readImages` | `true` | Учитывать изображения страницы в знаниях (товары/иллюстрации; мелкие <48px и дубликаты отбрасываются) |
| `vision` | `false` | Дополнительно описывать изображения через vision-модель (`images` в запросе к LLM). По умолчанию выключено — дороже и медленнее |
| `sound` | `true` | Звуковой сигнал и бейдж непрочитанного, когда приходит новое сообщение, а виджет закрыт |
| `checkinAfter` | `180` | Через сколько секунд тишины клиента ИИ сам спросит «Ваш вопрос решён?» (`0` — выключить). Если «да» — запрашивает оценку и закрывает тикет, если «нет» — предлагает продолжить или позвать оператора |

### Настройки агента — в админке

Настройки ИИ убраны из виджета (здесь больше нет шестерёнки и панели настроек). В backend-режиме их ведёт оператор в админ-панели. Панель состоит из четырёх вкладок:

- **Чаты** — список диалогов с фильтрами «Все / Оператор / Нерешённые / Закрытые», переписка и ответы.
- **Статистика** — сайты с агентом, онлайн, ответы, нерешённые, средняя оценка (виджет предлагает её при закрытии диалога), популярные запросы и таблица нерешённых запросов со ссылкой «открыть →» прямо в чат.
- **Данные и инструкции** — CRUD базы инструкций агента (текст + сайт) и все нерешённые вопросы.
- **Настройки** — провайдер (`ollama`/`openai`/`openrouter`/`groq`/`mistral`/`custom`), endpoint, модель, API-ключ, адрес отправителя `from`, флаг «спрашивать email», глобальные инструкции, **срок хранения тикетов** (`ticketTtlDays`), **SMTP-сервер** для реальной отправки писем и **Discord-вебхук** для уведомлений. Сохранение пишет их в `server/config.json` (PUT `/api/config`).

### Уведомления в Discord

В админке (**Настройки → Уведомления в Discord**) или в `server/config.json` можно указать webhook — тогда сервер шлёт в канал embed-сообщения о событиях: новый чат, запрос оператора, нерешённый вопрос, оценка диалога, ответ оператора. Уведомления уходят асинхронно (не тормозят ответы) и аккуратно троттлятся.

```json
"discordWebhook": "https://discord.com/api/webhooks/<id>/<token>",
"discordUsername": "Adaptive Widget",
"discordAvatar": "",
"discordInsecure": false
```

Пустой `discordWebhook` выключает уведомления. Секрет удобно держать в `server/config.json` (он в `.gitignore`) или в переменной окружения `AW_DISCORD_WEBHOOK`. Если корпоративный прокси/антивирус подменяет TLS-сертификаты и Node пишет `CERT…`/`unable to get local issuer certificate`, включите `discordInsecure: true` (или `AW_DISCORD_INSECURE=1`) — проверка сертификата для вебхука будет отключена.

### Кнопки клиента, статусы и чек-ин

В нижней части виджета клиент видит две кнопки: **«Позвать оператора»** и **«Вернуть ИИ»** — переключение между ИИ-агентом и оператором прямо из чата (вторая появляется, когда подключён оператор). Email и телефоны в ответах агента автоматически подсвечиваются акцентным цветом и превращаются в ссылки `mailto:`/`tel:`. Если клиент долго молчит после ответа агента (`checkinAfter`), ИИ сам спрашивает, решён ли вопрос: «да» → оценка и закрытие тикета (`POST /api/chat/:id/resolve`), «нет» → продолжить с ИИ или позвать оператора. В админке диалог показан двусторонним (клиент справа, ИИ/оператор слева), а чаты подсвечиваются статусами **«Общается с ИИ»**, **«Ждёт оператора»** (пульсирующий жёлтый), **«Оператор отвечает»** и **«Закрыт»**.

**Режим только ИИ**: админка (**Настройки → Операторы включены**, ключ `operatorsEnabled` в `server/config.json`) может отключить операторов — клиентам скрываются кнопки переключения (хост получает `data-noop`), `handoff` и `reply` отклоняются сервером (`400 operators_disabled`), чек-ин предлагает только «Продолжить с ИИ». Флаг приходит виджету через `/api/init`, поэтому сервер может переопределить настройку страницы.

### Адаптивность и анимации

Виджет сам масштабируется под окно: на планшете становится шире, на телефоне (≤460px) разворачивается во весь экран, высота учитывает мобильные панели браузера (`--pw-vh`, отслеживается `visualViewport`). Анимации переведены на плавные кривые (`cubic-bezier`), есть поддержка `prefers-reduced-motion`. Демо-страницы адаптивны (breakpoints 900/640/400px), а тема и цветовая палитра переключаются **выпадающими списками** в шапке — при переключении виджет перекрашивается плавно и **не открывается**, если был закрыт.

### Статус подключения ИИ

В шапке виджета отображается состояние: `AI: qwen2.5:3b · Ollama` (зелёный), `AI: gpt-4o-mini · OpenAI` (зелёный), или нейтральное `ИИ отключён · отвечаю по данным сайта` (жёлтое). Последнее — **не** ошибка: без рабочей LLM виджет честно отвечает поиском по данным страницы.

| `/api/chat/:id/message` | Сообщение (AI-ответ на сервере / пересылка оператору) |
| `/api/chat/:id/rating` | Оценка диалога клиентом (звёзды 1–5) |
| `/api/chat/:id/{handoff,mode,reply,instructions,events,full,close}` | Перевод оператору, возврат ИИ, ответ оператора, инструкции, SSE-канал, снимок, закрытие |
| `/api/stats` | Статистика: сайты, онлайн, ответы, оценки, популярные/нерешённые запросы (с `chatId`), размер/попадания кэша ответов |
| `/api/instructions` | GET/POST/DELETE — база инструкций агента (KB, требуют `adminToken`) |
| `/api/config` | GET/PUT — настройки агента: провайдер, модель, инструкции, база Q&A, порог схожести, `ticketTtlDays`, SMTP (админка, требуют `adminToken`) |
| `/api/smtp/test` | POST — отправить тестовое письмо через SMTP и вернуть `{ ok, to, mode }` (админка, требует `adminToken`) |
| `/api/faq` | Частые вопросы для чипов виджета: популярные запросы + Q&A из конфига (публичный) |
| `/admin` | Админ-панель агентов: вкладки «Чаты», «Статистика», «Данные и инструкции», «Настройки» |
| `/demo` | Демо-страница виджета (GadgetHub), виджет подтягивается с этого же сервера |
| `server/data/answers-cache.json` | Кэш ответов агента (вопрос → ответ), повторные вопросы не тратят токены |
