# Режим 1: RAG на сервере (`agentMode: "rag"`)

**Это значение по умолчанию** и то, что было реализовано раньше. Виджет на сайте только показывает ответ — всю работу делает сервер поддержки.

## Как работает

1. Клиент открывает виджет и шлёт вопрос на сервер (`POST /api/chat/<id>/message`).
2. Сервер проверяет **кэш** (один и тот же вопрос не бьётся в модель повторно) и **базу Q&A** из конфига.
3. Если готового ответа нет — сервер берёт знания сайта (передаются при `init`), ищет релевантные фрагменты (взвешенный поиск по токенам) и склеивает контекст.
4. Весь контекст + вопрос отправляются модели **одним запросом** (`/v1/chat/completions`), модель отвечает.
5. Если модель недоступна — сервер отвечает локальным поиском по знаниям, чтобы чат не молчал.

Это классический **RAG (retrieval-augmented generation)**: сервер сам решает, какой контекст подсунуть модели.

## Запуск

```bash
node server/server.js          # порт 3000
# в админке /admin: Настройки агента -> Режим -> "RAG на сервере"
# либо в server/config.json: "agentMode": "rag"
```

Плюсы: тесты `server.test.js` (48 проверок), включает режимы Q&A, кэш, операторы, логи, статистику.

## Технические детали

### Фреймворк

Режим тоже реализован **на нативном Node.js без сторонних библиотек**: один запрос к OpenAI-совместимому эндпоинту через встроенный `fetch`. Сторонние RAG/LLM-фреймворки (LlamaIndex, LangChain) не используются — конвейер «поиск → контекст → промпт → ответ» собран вручную в `server/lib/ai.js`.

### Запрос к модели

Один вопрос — один POST на `cfg.endpoint` (по умолчанию `http://localhost:11434/v1/chat/completions`):

```json
{
  "model": "qwen2.5:3b",
  "messages": [
    { "role": "system", "content": "Ты — ИИ-агент сайта «…». Отвечай кратко…\n\nДанные сайта:\n[Наушники Aurora X] Беспроводные… Цена: 7990…\n\n[Как оформить возврат] …" },
    { "role": "user", "content": "Сколько стоят наушники?" }
  ],
  "temperature": 0.3
}
```

Заголовки: `Content-Type: application/json`, при заданном `apiKey` — `Authorization: Bearer <key>`.

### Как собирается контекст (`server/lib/ai.js`)

- `tokenize`/`terms` — нормализация текста, разбиение на токены; `uniqueArr` — дедупликация.
- `contextFor(knowledge, q)` — взвешенный поиск по токенам (вхождение в заголовок или содержимое), сортировка по числу совпадений; берутся **топ-6 фрагментов по ≤600 символов**, склеиваются в текст контекста. Если совпадений нет — берутся первые 6 фрагментов, чтобы у модели был хоть какой-то контекст.
- `buildPrompt` — собирает `system`: роль агента + «Данные сайта: <контекст>» + дополнительные инструкции поддержки.
- `askLLM` — выполняет запрос, возвращает `message.content` или `null` (любая ошибка сети/API тихо превращается в `null`).

### Fallback (когда модель недоступна)

1. `askLLM` вернул `null` → `findBest(knowledge, q)` — тот же поиск по токенам: точное сопоставление, порог качества `conf >= 0.35` (при молочисленных совпадениях может взять второй по релевантности кандидат).
2. Если найден фрагмент → ответ = `item.content`, источник помечается `search`.
3. Иначе — `null`, и сервер отвечает стандартным fallback-текстом с контактом поддержки.

### Цепочка генерации ответа (`server/server.js`)

```
кэш (answers-cache.json) → база Q&A (matchQA, конфиг) → LLM/RAG →
→ локальный поиск (fallback) → стандартный текст «Не нашёл точного ответа» + email
```

Каждое попадание пишется в `chat.hits` с источником: `cache`, `qa`, `llm`, `search`. Ответ от LLM, найденный фрагмент и Q&A одинаково попадают в кэш.

## Плюсы

- **Проще.** Один запрос к модели, проще дебажить и объяснять.
- **Быстрее.** Нет дополнительных кругов между моделью и инструментами — для маленьких моделей это заметно.
- **Предсказуемо.** Ответы стабильны: что в контексте — то и источник.
- **Экономичнее.** Каждый вопрос = ровно 1 вызов модели.

## Минусы

- Слабая модель может «утонуть» в большом контексте: если знаний на сайте много, релевантность падает.
- Весь контекст шлётся на каждом вопросе, даже если нужна одна строчка — дороже по токенам на запрос.
- Нет возможности у модели самой «добрать» данные: она отвечает тем, что дали. Если поиск не нашёл нужный фрагмент — ответ будет неточным.
