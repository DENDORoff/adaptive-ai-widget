# Концепция: Адаптивный ИИ-виджет для сайтов

## Проблема

Большинство чат-ботов на сайтах (LiveChat, Chatwoot, Tars, Tidio) — статичны:
- Заказчик ** weeks вручную** загружает ответы в конструктор
- При изменении контента виджет «выключается» и требует обновления
- Виджет визуально **выпадает** из дизайна сайта — общий白 box в углу
- Нет настоящего понимания контекста вопроса, только шаблонные ответы
- Ручной перевод на другой язык

## Решение

**Zero-Config Адаптивный ИИ-Агент** — один `<script>` на страницу. Виджет **сам**:

1. **Извлекает структуру и данные сайта** (JSON-LD, заголовки, FAQ, товары, контакты)
2. **Подстраивает стиль под дизайн** (цвета из CSS-переменных, шрифт, темная/светлая тема, радиусы)
3. **Отвечает на основе реальных данных** страницы (поиск по извлечённому контенту)
4. Опционально подключает **LLM-модель** как достоверный RAG-слой — локальную (Ollama) или облачную по API-ключу (OpenAI, OpenRouter, Groq, Mistral, свой сервер)
5. Напоминает бренд — **выглядит как часть сайта**

## Уникальность (vs существующие решения)

| Критерий | Tidio / LiveChat | Агент (наш виджет) |
|---|---|---|
| Конфигурация | Ручная, часы работы | Автоматически при подключении |
| Обновление данных | После каждого изменения контента | Автоматическая пересборка |
| Стиль | Общий шаблон | Адаптация к CSS сайта |
| Ответы | Фиксированные сценарии | Поиск по данным + LLM (Ollama локально) |
| Мультиязычность | Ручной перевод | Авто-определение языка |
| Данные / безопасность | Облако, данные у вендора | **По выбору: локально (Ollama) или свой ключ** |

## Как это устроено (архитектура)

```
Пользователь → Вопрос
        ↓
┌───────────────────────────────────┐
│       Адаптивный ИИ-Агент        │
├───────────────────────────────────┤
│  1. Экстракция стиля сайта       │  ← getComputedStyle(), CSS variables
│  2. Экстракция знаний            │  ← JSON-LD, headings, FAQ, products
│  3. Построение индекса            │  ← tokenization, scoring
│  4. Поиск ответа                 │  ← weighted TF matching
│  5. ИИ-ответ (RAG)               │  ← Ollama локально или облачный API, топ-6 фрагментов
└───────────────────────────────────┘
        ↓
  Ответ с источником
```

### Экстракция стиля
- Считывает CSS-переменные: `--brand`, `--primary`, `--accent`, `--color-primary`
- Если переменных нет — берёт цвет ссылки / кнопки как primary
- Определяет тёмную/светлую тему через `luminance(body.background)`
- Берёт шрифт, радиусы кнопок, логотип из шапки

### Экстракция знаний (零 config)
- `application/ld+json` (Product, FAQPage, Organization)
- Заголовки `h1-h3` + идущий за ним текст
- Блоки с class `faq*`, `question*`, `product*`, `card*`
- Навигационные ссылки → разделы
- `mailto:`, `tel:` → контакты

## MVP фичи
- [x] Автоматическая адаптация стиля
- [x] Автоматическое извлечение знаний
- [x] Поиск по извлечённому контенту
- [x] Shadow DOM изоляция
- [x] Подсказки (чипы) из заголовков
- [x] Локальный ИИ через Ollama (RAG, qwen2.5:3b)
- [x] Облачные LLM по API-ключу: OpenAI, OpenRouter, Groq, Mistral, свой endpoint
- [x] Статус подключения AI (health-check Ollama / статус провайдера)
- [x] Отладочная информация `window.__ADAPTIVE_DEBUG__`

## Ограничения
- Работает с контентом, доступным в DOM на момент загрузки (SSR / initial HTML)
- Виджет не заменяет CRM-интеграции (он отвечает на вопросы по сайту)
- Для Ollama на клиентском сервере нужны ресурсы (CPU/GPU) — на слабом железе ответы медленные
- Локальные модели уступают GPT-4 по «пониманию» сложных вопросов → используется RAG с данными сайта
- Короткие / размытые вопросы могут получить общий ответ
