# Приложение: режимы ИИ-агента

ИИ-агент на сервере поддержки умеет отвечать на вопросы клиентов двумя способами. Оба живут в `server/server.js` (+ `server/lib/ai.js` и `server/lib/agent.js`) и переключаются **одной настройкой** — `agentMode` в `server/config.json` или селектором «Режим работы ИИ-агента» в админке `/admin`.

| | **Вариант 1: RAG на сервере** | **Вариант 2: агент с инструментами** |
|---|---|---|
| `agentMode` | `"rag"` (по умолчанию) | `"tools"` |
| Даёт ли модель себе контекст | Нет — сервер ищет и отдаёт весь контекст сразу | Да — модель сама вызывает `search_knowledge` |
| Запросов к модели на вопрос | 1 | 1–4 (лимит 4 раунда) |
| Скорость | Быстро | Медленнее (кругов на CPU-модели — секунды) |
| Точность на большом сайте | Падает: модель «тонет» в длинном контексте | Выше: запрашивается только нужное |
| Стоимость токенов | Контекст едет целиком на каждый вопрос | Контекст короткий, но вывод генерируется в каждом раунде |
| Требования к модели | Любая OpenAI-совместимая | Обязательно function calling (qwen2.5:3b, llama3.1+, gpt-4o…) |
| Расширяемость инструментами | Нет | Да (заказ, склад, время…) |
| Код | `server/lib/ai.js` | `server/lib/agent.js` |
| Фреймворк | Нативный Node.js (`fetch`), без библиотек | Собственный движок цикла (~90 строк) поверх протокола OpenAI **function calling** (`tools`/`tool_calls`), без библиотек |
| Проверено | 48 тестов `server.test.js` + живая Ollama | тесты + живая Ollama (qwen2.5:3b) |

## Техническая реализация: что общего в коде

Оба режима крутятся в одном процессе `server/server.js` и делят один поиск по знаниям (`contextFor`, `findBest` в `server/lib/ai.js`). Различается только стратегия подачи контекста в модель:

- `rag` → `ai.answer` (в `server/lib/ai.js`): сервер собирает контекст в `system`-промпт, **один** запрос к `/v1/chat/completions`, без `tools`.
- `tools` → `agent.agentAnswer` (в `server/lib/agent.js`): модель получает вопрос без контекста, инструмент `search_knowledge` (JSON Schema) и сама вызывает его; цикл повторяет запросы с сообщениями `role: "tool"` до финального ответа (лимит 4 раунда).

Ни LangChain/LangGraph, ни Vercel AI SDK, ни LlamaIndex в проект не установлены — «фреймворком» служит родной протокол OpenAI-compatible function calling плюс нативный Node.js `fetch`. Подробные схемы запросов, кода и обработки ошибок — в `docs/MODE_SERVER_RAG.md` и `docs/MODE_AGENT_TOOLS.md`.

## Что общего (у обоих режимов)

- Сначала проверяется **кэш** ответов (`answers-cache.json`) — одинаковый вопрос не бьётся в модель повторно.
- Затем — **база Q&A** из конфига (работает даже без модели).
- Если модель недоступна — сервер отвечает **локальным поиском** по знаниям сайта.
- Всё логируется: источник ответа (`llm`, `tools`, `qa`, `cache`, `search`), чаты, stats, email операторов.
- Виджету всё равно, какой режим: он шлёт вопрос на сервер и получает ответ.

## Как выбирать

**Берите `rag`, если:**
- сайт маленький (до ~50 фрагментов знаний),
- важна скорость и простота,
- модель слабее/дешевле (или локальная CPU-модель),
- хотите предсказуемые ответы и минимум движущихся частей.

**Берите `tools`, если:**
- знаний на сайте много и вопросы специфичные,
- хотите «честного» агента, который сам добирает данные,
- модель поддерживает tool-calling и вам не жалко пары лишних секунд,
- впереди — интеграция с внешними системами (заказы, склад, время работы).

## Советы

- Для демо на локальной Ollama с `qwen2.5:3b` оба режима работают; `rag` ощутимо отзывчивее на CPU.
- Если переключились на `tools`, а модель не поддерживает function calling — агент молча вернётся к поиску по знаниям (ответ не потеряется, но задуман уровень «агента» будет ниже).
- Режим меняется на лету через админку, сервер перезапускать не нужно.
