# Режим 2: агент с инструментами (`agentMode: "tools"`)

Другой способ давать модели данные сайта: вместо того чтобы впихнуть весь контекст в одно сообщение, модель **сама вызывает инструмент `search_knowledge`**, когда ей нужна информация, и только потом формулирует ответ.

Это «настоящая» агентская архитектура (tool-calling / function calling): цикл `модель → вызов инструмента → результат → модель →…→ финальный ответ`.

## Как работает

1. Сервер получает вопрос (после кэша и базы Q&A — так же, как в режиме `rag`).
2. Модели отправляется вопрос **без контекста**, но со списком инструментов (`tools`). Один инструмент — `search_knowledge`.
3. Модель сама решает, нужен ли поиск. Если нужен — возвращает `tool_calls: [{ name: "search_knowledge", arguments: {...} }]`.
4. Сервер выполняет инструмент (тот же взвешенный поиск по знаниям сайта) и возвращает результат в диалог как сообщение `role: "tool"`.
5. Модель видит результат и выдаёт финальный ответ. При необходимости цикл повторяется (до 4 раундов).

Код — `server/lib/agent.js`. Отвечает только на основе полученного из инструмента контекста.

## Запуск

```bash
node server/server.js          # порт 3000
# в админке /admin: Настройки агента -> Режим -> "Агент с инструментами"
# либо в server/config.json: "agentMode": "tools"
```

**Требование:** модель должна уметь function calling. Для Ollama это `qwen2.5:3b` (проверено вживую) и большинство `qwen3`/`llama3.1+`; для OpenAI — gpt-4o, для Groq — llama-3.3-70b.

## Плюсы

- **Модель сама решает, что искать.** Вопрос «сравни два товара» → модель сделает два поиска, а не один «усреднённый».
- **Маленький контекст.** В модель не едет весь сайт — только то, что она реально запросила. Для больших баз знаний это точнее и дешевле по токенам.

  *Пример из живой проверки (qwen2.5:3b, локальная Ollama): вопрос «Напиши цену наушников Aurora X» → модель вызвала `search_knowledge`, получила данные и ответила: «Цена наушников Aurora X — 7990 рублей. Доставка по России занимает 2-7 дней.»*

- **Расширяемость.** Инструменты можно добавлять: `current_time`, `get_order_status`, `check_stock` — модель сама начнёт ими пользоваться.
- **Честность.** Если данных нет, модель может прямо сказать «не знаю» вместо того, чтобы путаться в куче контекста.

## Минусы

- **Медленнее.** Несколько вызовов модели на один вопрос (на CPU-моделях вроде qwen2.5:3b это секунды).
- **Сложнее.** Нужна модель с tool-calling; нужно следить за корректностью `arguments` (JSON), обрабатывать пустые результаты.
- **Дороже при больших токах вывода.** Каждый раунд генерирует токены, а не только финальный ответ.
- **Риск зацикливания.** Модель может долго «искать», поэтому стоит жёсткий лимит раундов (4).
