# Уникальные возможности

Документ описывает возможности, которых нет у типовых чат-виджетов (Tidio, Chatwoot, Intercom): они либо требуют ручной настройки, либо недоступны в бесплатных тарифах.

## 1. AI-подбор стиля, когда на сайте нет фирменных цветов

**Проблема:** виджет читает `--brand`/`--accent` из CSS, но у многих сайтов этих переменных нет — тогда виджет выглядел чужеродно.

**Решение:** если фирменных цветов не нашлось (`PALETTE.found === false`), виджет при включённом `aiStyle` (по умолчанию `true`) спрашивает у LLM палитру под тематику сайта и применяет её: `primary`, `accent`, `bg`, `dark`, `radius`.

```html
<script>
window.ADAPTIVE_WIDGET = { aiStyle: true };
</script>
```

- Если LLM недоступна, виджет молча остаётся на цветах по умолчанию — ничего не ломается.
- Палитру можно посмотреть в отладке: `window.__ADAPTIVE_DEBUG__.palette` (поле `_ai` — подобрана ИИ, `found` — нашлись фирменные цвета).

## 2. Изображения страницы в знаниях (и опциональный vision)

Виджет собирает `<img>` со страницы и добавляет их к товарам/записям знаний (кап 12 изображений, дедупликация по `src`, пропуск мелких <48px и служебных картинок). При повторе названия товара новые URL добавляются в существующую запись (до 5).

```html
<script>
window.ADAPTIVE_WIDGET = {
  readImages: true,  // по умолчанию включено
  vision: false      // опционально: LLM описывает картинки (дороже и медленнее)
};
</script>
```

- `readImages` — дешёвый режим: ИИ просто знает, что у товара есть изображение, и может сослаться на него.
- `vision: true` — виджет отправляет изображения в LLM (поле `images`, OpenAI-совместимый формат) и получает текстовое описание. Требует vision-модель (например, `gpt-4o-mini`, `qwen2.5-vl`).
- `data:`-URI тоже поддерживаются (в знаниях длинная ссылка обрезается до 120 символов).

## 3. Email — рекомендуем, но не навязываем

Раньше перед чатом email был обязателен. Теперь по умолчанию в backend-режиме он **необязательный**: клиенту показывают поле с подсказкой «you@example.com · Enter — пропустить», и он может нажать Enter без адреса.

```html
<script>
window.ADAPTIVE_WIDGET = {
  backend: 'https://chat.yoursite.ru',
  askEmail: 'optional'   // true — обязательно, 'optional' — можно пропустить, false — не спрашивать
};
</script>
```

Зачем email всё же нужен: если клиент закроет вкладку до ответа оператора, сервер сможет отправить ответ письмом. При пропуске email такой возможности нет, но диалог всё равно ведётся и виден в админке.

## 4. Звук и состояние «сайт открыт, виджет закрыт»

Самая частая ситуация: пользователь ушёл на другую вкладку или закрыл виджет, а оператор ему ответил. Виджет сообщает об этом так:

- **звуковой сигнал** (двухтональный, включён по умолчанию, `sound: true`);
- **бейдж с числом непрочитанных** на кнопке виджета;
- **пульсирующий ореол** вокруг кнопки;
- обновлённый текст тизера.

При открытии панели счётчик сбрасывается. Звук включается только после первого действия пользователя (требование браузеров к автоплею).

```html
<script>
window.ADAPTIVE_WIDGET = { sound: false };  // отключить сигнал
</script>
```

## 5. Автоудаление тикетов по TTL

Диалоги не копятся вечно: `ticketTtlDays` (по умолчанию 14 дней) удаляет старые тикеты из `chats.json`. `0` — хранить бессрочно. Проверка идёт при старте сервера и раз в час.

Настраивается в админке (**Настройки → Хранение тикетов**) или в `server/config.json`:

```json
"ticketTtlDays": 14
```

## 6. База инструкций (KB) и нерешённые вопросы

В админке есть вкладка **«Данные и инструкции»**:

- инструкции агента (текст + сайт) можно добавлять, редактировать и удалять — они уходят в системный промпт;
- когда оператор отвечает в чате, его инструкции автоматически попадают в KB под именем `chat:<id>` (их можно позже переиспользовать);
- таблица «нерешённые вопросы» собирает запросы, на которые агент не ответил, со ссылкой «открыть →» прямо в нужный чат.

Эндпоинты (нужен `adminToken`): `GET/POST/DELETE /api/instructions`. Хранилище — `server/data/instructions.json` (кап 500 записей).

## 7. Настоящая отправка почты (SMTP)

Без настройки письма попадают в outbox (`server/data/email.log.ndjson`) и видны в админке. С настройкой SMTP сервер реально отправляет их клиенту (ответы оператора, тестовые письма).

- Поддержка 465 (implicit TLS) и 587 (STARTTLS), AUTH PLAIN, таймаут 15 секунд.
- Клиент написан на встроенных `net`/`tls` — **без npm-зависимостей**.
- Пароль приложения (Яндекс/Gmail/Mail.ru), пресеты и статус — в админке.

```json
"smtp": {
  "host": "smtp.yandex.ru",
  "port": 465,
  "secure": true,
  "user": "support@deworld.su",
  "pass": "app-password",
  "from": "support@deworld.su"
}
```

## 8. Живая смена темы и палитры без перезагрузки

Демо-страницы умеют переключать светлую/тёмную тему и фирменные цвета на лету, а виджет мгновенно подхватывает изменения — без перезагрузки страницы.

```js
window.AdaptiveWidget.refresh();                    // перечитать стиль/знания страницы и перекраситься
window.AdaptiveWidget.palette();                    // текущая палитра
window.AdaptiveWidget.open();                       // открыть / close() / toggle()
```

Что происходит при `refresh()`: повторная экстракция CSS-переменных и темы, пересборка знаний и индекса, перерисовка панели с короткой анимацией (`themeSwap`/`themePop`). Виджет не дублируется — хост переиспользуется.

Демо (тема и палитра — выпадающими списками в шапке):

- `demo/index.html`, `demo/backend.html` — светлые, 6 палитр;
- `demo/dark-store.html` — тёмная по умолчанию, светлая тема из списка.

При смене темы/палитры виджет перекрашивается с анимацией, но **не открывается**, если был закрыт (анимация `themePop` применяется только к открытой панели).

В футере демо — соцсети и сайт-спонсор: `discord.deworld.su`, `telegram.deworld.su`, `vk.deworld.su`, `max.deworld.su`, `youtube.deworld.su`, `tiktok.deworld.su` и `deworld.su`.

Админка тоже живая: список чатов обновляется каждые 3 секунды, открытый диалог — без перезагрузки (новые сообщения появляются с анимацией), статистика — каждые 5 секунд. Индикатор в шапке пульсирует, когда сервер на связи.

## 9. Уведомления в Discord

Команда видит происходящее в поддержке, не открывая админку: сервер отправляет embed-сообщения в Discord-вебхук.

- События: новый чат, запрос оператора (handoff), нерешённый вопрос, подтверждение решения (`resolved`), возврат к ИИ (`resume`), оценка диалога, ответ оператора.
- Отправка асинхронная и с троттлингом (не блокирует ответы клиенту), таймаут 8с, ошибки не роняют сервер.
- Настраивается в админке (**Настройки → Уведомления в Discord**) или в `server/config.json`:
  - `discordWebhook` — URL вебхука (пусто = выключено);
  - `discordUsername` / `discordAvatar` — имя и аватар бота;
  - `discordInsecure` — отключить проверку TLS-сертификата (нужно, если корпоративный прокси/антивирус подменяет сертификаты и Node пишет `CERT…`).
- Секрет не коммитится: `server/config.json` в `.gitignore`, также поддерживается `AW_DISCORD_WEBHOOK`.

## 10. Автомасштабирование и плавные анимации

Виджет автоматически подстраивается под размер окна:

- ≤600px — панель становится шире (лист у нижнего края);
- ≤460px — разворачивается **во весь экран**;
- высота считается от `--pw-vh`, который обновляется по `resize` и `visualViewport` (корректно с мобильными панелями браузера и клавиатурой);
- `prefers-reduced-motion` отключает анимации.

Анимации переведены на плавные кривые (`cubic-bezier(.22,1,.36,1)` и «пружины» для hover): открытие панели, появление сообщений, чипы, звёзды оценки, кнопки. Демо-страницы адаптивны (900/640/400px) и тоже анимированы.

## 11. Клиент управляет режимом: оператор / ИИ, чек-ин и акцентные контакты

- В нижней части виджета — две кнопки: **«Позвать оператора»** (`POST /api/chat/:id/handoff`) и **«Вернуть ИИ»** (`POST /api/chat/:id/resume`). Видна всегда только актуальная кнопка; сервер сообщает смену режима клиенту по SSE (`mode`).
- **Акцентное форматирование**: email и телефоны в сообщениях агента превращаются в ссылки `mailto:`/`tel:` и подсвечиваются фирменным цветом (`.hl`).
- **Чек-ин**: если клиент молчит `checkinAfter` секунд (по умолчанию 180, `0` — выключено) после ответа агента, ИИ сам спрашивает «Ваш вопрос решён?».
  - «Да, решено» → `POST /api/chat/:id/resolve` (тикет закрывается) и предложение оценки 1–5.
  - «Нет, нужна помощь» → кнопки «Позвать оператора» и «Продолжить с ИИ».
- **Админка**: переписка показана двусторонней — клиент справа (синий), ИИ-агент и оператор слева (с аватарами и легендой). Статусы чатов подсвечиваются: **«Общается с ИИ»**, **«Ждёт оператора»** (пульсирующий жёлтый, если оператор ещё не ответил), **«Оператор отвечает»**, **«Закрыт»**.
- **Режим только ИИ** (`operatorsEnabled: false` в админке → **Настройки → Операторы включены**): клиентам скрываются кнопки «Позвать оператора»/«Вернуть ИИ» (хост получает `data-noop`), `handoff` и админ-ответ `reply` отклоняются сервером (`400 operators_disabled`), чек-ин предлагает только «Продолжить с ИИ». Флаг передаётся виджету через `/api/init` (сервер может переопределить клиентскую настройку).

## 12. Эксперимент: вкладка «Муха» — чат и 3D коннектома

- Отдельная вкладка в виджете: **чат** с оцифрованным мозгом плодовой мухи и **3D-визуализация** нейронов (three.js, подгружается только при открытии вкладки, при недоступности — статус-плейсхолдер без падения).
- Данные берёт сервер: живые запросы к **NeuPrint** (`neuprint.janelia.org`, ключ `flyBase`) через прокси: `/api/fly/status`, `/api/fly/chat`, `/api/fly/neurons`, `/api/fly/neuron/:id`.
- Если NeuPrint недоступен — офлайн-справочник (`server/lib/fly.js`): базовые факты (гемибрейн ~21,6 тыс. нейронов и ~14 млн синапсов, полный мозг 2024 — ~139 тыс.) и демо-нейроны (KC, MBON, DAN, PN, фоторецептор) с генерацией 3D-координат.
- Управление: `flyEnabled` (по умолчанию `true`) в админке полностью скрывает вкладку; флаг приходит виджету через `/api/init` (`data-nofly`).
